# QCM — QIDI Camera Manager 0.2.0-alpha1

QCM (QIDI Camera Manager) is a lightweight management layer for the camera stack of QIDI Q1 Pro.

The main purpose of QCM is not to replace the QIDI firmware stack permanently, but to provide a controlled abstraction layer that can select and manage different camera backends while preserving rollback to the pre-installation state.

This release focuses on safe configuration management, backend switching, health checks, rollback and an offline installation/repair/restore mechanism.

---

## 1. Architecture

The general architecture is:

```text
QIDI Q1 Pro
│
├── Klipper
├── Fluidd / QIDI WebUI
│
├── Stock camera backend
│   └── webcamd
│       └── mjpg-streamer
│
└── QCM
    ├── webcamd backend
    │
    └── crowsnest backend
        └── uStreamer
            └── V4L2
                └── /dev/video4
```

QCM owns the decision about which camera backend is currently active.

The original QIDI `webcamd` installation is not deleted by QCM.

When the `crowsnest` backend is selected, QCM stops/disables the stock `webcamd` service and starts/manages the QCM Crowsnest service.

When the `webcamd` backend is selected, QCM restores the stock backend and disables the QCM Crowsnest service.

## 3. Camera configuration

QCM uses:

```text
/home/mks/klipper_config/webcam.txt
```

The file remains shell-compatible and can contain the QIDI legacy option:

```text
camera_usb_options="-r 1280x720 -f 30 -d /dev/video4"
```

QCM adds its own configuration variables:

```text
QCM_BACKEND
QCM_DEVICE
QCM_RESOLUTION
QCM_FPS
QCM_HOST
QCM_PORT
QCM_V4L2_CONTROLS
QCM_BACKEND_OPTIONS
```

Example:

```text
QCM_BACKEND="crowsnest"
QCM_DEVICE="/dev/video4"
QCM_RESOLUTION="1280x720"
QCM_FPS="30"
QCM_HOST="127.0.0.1"
QCM_PORT="8080"
QCM_V4L2_CONTROLS="brightness=0,contrast=1,saturation=80,gamma=84,gain=1,sharpness=2,backlight_compensation=0"
QCM_BACKEND_OPTIONS="crowsnest.log_path=/tmp/crowsnest.log;crowsnest.log_level=quiet;crowsnest.delete_log=true;crowsnest.no_proxy=false;cam1.mode=mjpg"
```

`webcam.txt.example` contains the example Crowsnest configuration used by this release.

## 4. Backend abstraction

QCM currently supports two backends.

### 4.1. webcamd

The stock QIDI backend.

Service:

```text
webcamd.service
```

Executable:

```text
/usr/local/bin/webcamd
```

QCM does not replace or modify the original executable.

---

### 4.2. crowsnest

The alternative backend bundled with this release.

Service:

```text
crowsnest-qidi.service
```

Runtime:

```text
/opt/qidi-camera/crowsnest
```

Crowsnest uses uStreamer for the MJPEG HTTP stream.

The camera is accessed through:

```text
/dev/video4
```

The normal QIDI HTTP path remains:

```text
/webcam/
```

and is served by the existing QIDI nginx configuration.

QCM therefore does not require changes to the QIDI WebUI.

## 5. Crowsnest runtime

This release contains a minimal Crowsnest legacy/v3 runtime required for the selected MJPEG backend.

The runtime does not contain:

```text
.git
source repository history
build tree
unused uStreamer binaries
RTSP server binaries
```

The bundled uStreamer executable is:

```text
crowsnest/bin/ustreamer/ustreamer
```

The runtime also contains the required static web files under:

```text
crowsnest/ustreamer-www/
```

The original Crowsnest and uStreamer license files are included in the package.

---

## 6. Crowsnest modifications

The bundled Crowsnest runtime is based on the tested legacy/v3 code.

Several modifications were made specifically for the offline QIDI runtime:

1. The mandatory RTSP binary check was removed.
2. RTSP version detection was removed.
3. uStreamer version detection no longer depends on Git metadata.
4. Crowsnest self-version reporting no longer depends on `.git`.
5. The runtime can therefore operate without the original Git repository.
6. The Crowsnest runtime uses the bundled uStreamer binary directly.

RTSP support is not used by QCM in this release.

The file:

```text
crowsnest/libs/rtspsimple.sh
```

is intentionally retained to minimize changes to the tested legacy/v3 runtime.

## 7. Generated Crowsnest configuration

When the `crowsnest` backend is active, QCM generates:

```text
/opt/qidi-camera/config/crowsnest.conf
```

The current tested configuration is equivalent to:

```ini
[crowsnest]
log_path: /tmp/crowsnest.log
log_level: quiet
delete_log: true
no_proxy: false

[cam 1]
mode: mjpg
port: 8080
device: /dev/video4
resolution: 1280x720
max_fps: 30
v4l2ctl: brightness=0,contrast=1,saturation=80,gamma=84,gain=1,sharpness=2,backlight_compensation=0
```

The generated configuration is runtime state and is not used as a static release configuration.

## 8. Transaction model

QCM does not simply rewrite the camera configuration and hope that the backend starts.

The configuration pipeline is:

```text
parse
  ↓
validate
  ↓
capability check
  ↓
generate backend configuration
  ↓
apply
  ↓
healthcheck
  ↓
commit
```

If application or healthcheck fails:

```text
apply
  ↓
FAIL
  ↓
restore known-good configuration
  ↓
restore backend state
  ↓
restore V4L2 controls
  ↓
healthcheck
```

This is intended to prevent an invalid camera configuration from permanently breaking camera access.

---

## 9. Known-good configuration

QCM stores the internal known-good configuration in:

```text
/opt/qidi-camera/qcm/state/known_good.conf
```

The file is intended to be root-only internal state.

A read-only mirror is maintained in `webcam.txt` for diagnostics and visibility.

Additional state files may include:

```text
accepted.conf
status.json
rejected.conf
rejected.reason
```

These files are runtime state and are not part of the release archive.

---

## 10. Healthcheck

Health checking is part of the QCM apply/rollback transaction.

The healthcheck verifies the selected backend and camera path rather than relying only on systemd state.

Checks include:

### Backend

The selected backend service must be operational.

### Backend HTTP snapshot

QCM verifies that the backend HTTP endpoint can return a valid JPEG image.

For the current Crowsnest backend:

```text
http://127.0.0.1:8080/?action=snapshot
```

### QIDI HTTP snapshot

QCM also checks the public QIDI path:

```text
http://127.0.0.1/webcam/?action=snapshot
```

This confirms that the complete chain through the existing QIDI HTTP layer is working.

### MJPEG stream

The stream endpoint is checked for actual data.

A normal MJPEG stream is intentionally endless, therefore a timeout after receiving data is not itself considered a failure.

## 11. CLI

Run QCM directly with:

```text
python3 /opt/qidi-camera/qcm/qcm.py
```

Available commands:

```text
qcm.py
qcm.py --check-config
qcm.py --self-test
qcm.py --list-controls
qcm.py --status
qcm.py --apply-once
qcm.py --dry-run
```

### --check-config

Validates the current `webcam.txt`.

### --self-test

Runs internal QCM tests.

### --list-controls

Lists detected V4L2 controls.

### --status

Displays the saved QCM state journal.

Important:

`--status` is not an independent live backend probe.

For example, an old `last_error` entry may remain in `status.json` even when the current QCM state is `RUNNING`.

### --apply-once

Applies the current configuration once and exits.

### --dry-run

Validates configuration and backend preparation without applying the change.

### --help

Displays available commands and usage.

## 12. systemd

QCM is installed as:

```text
/etc/systemd/system/qcm.service
```

The service runs as root because it manages system services, V4L2 controls and protected runtime state.

The service uses:

```text
Restart=always
RestartSec=2
```

The QCM service is enabled during installation.

---

## 13. Crowsnest systemd service

The bundled Crowsnest service is:

```text
/etc/systemd/system/crowsnest-qidi.service
```

The service itself is not permanently enabled as an independent boot service.

QCM controls its lifecycle.

Typical active state while QCM uses Crowsnest:

```text
qcm.service             enabled / active
crowsnest-qidi.service  disabled / active
webcamd.service         disabled / inactive
```

This avoids running two camera servers against the same V4L2 device.

---

## 14. Why the stock webcamd is preserved

The QIDI firmware contains more than just a camera process.

The stock webcam stack may be referenced by:

```text
QIDI WebUI
Fluidd
QIDI Link
internal services
firmware updates
```

For this reason QCM does not delete:

```text
/usr/local/bin/webcamd
/etc/systemd/system/webcamd.service
```

The original installation remains available as a rollback target.

The release contains:

The installer is designed to operate without downloading the QCM/Crowsnest runtime.

The package itself contains:



## 17. install

Fresh installation:

```text
install.sh install
```

The installer:

1. checks the system;
2. detects the QIDI camera configuration path;
3. creates the original-state backup if one does not already exist;
4. installs QCM;
5. installs the bundled Crowsnest runtime;
6. installs QCM/Crowsnest systemd units;
7. installs the release Crowsnest configuration;
8. switches camera management to QCM;
9. performs healthcheck.

The installer refuses to perform a second independent `install` over an existing QCM installation.

For an already installed system use:

```text
repair
```

---

## 18. Persistent backup

The original pre-QCM state is stored outside the QCM runtime:

```text
/home/mks/.qcm-backup
```

The backup is created only once.

`repair` and later reinstall operations must not overwrite the original baseline.

The backup can contain:

```text
webcam.txt
manifest
```

The manifest records information such as:

```text
file existence
UID
GID
file mode
webcamd enabled state
webcamd active state
```

This allows uninstall/restore to return the printer to the state recorded before QCM installation.

---

## 19. repair

Run:

```text
install.sh repair
```

Repair reinstalls the known release runtime without replacing the original persistent baseline.

The original backup is preserved.

Repair is intended for:

```text
damaged runtime files
missing systemd units
manual file corruption
reinstallation of the same release
```

Repair does not intentionally replace the user's current valid QCM configuration with the factory example.

---

## 20. restore

Run:

```text
install.sh restore
```

Restore:

1. stops the QCM-controlled camera stack;
2. disables QCM;
3. restores the saved `webcam.txt`;
4. restores the saved file metadata;
5. restores the recorded `webcamd` enable/active state.

The goal is to return the camera stack to the pre-QCM installation state.

---

## 21. uninstall

Run:

```text
install.sh uninstall
```

Uninstall:

1. restores the saved original state;
2. stops QCM/Crowsnest;
3. disables QCM;
4. removes the QCM runtime;
5. removes the QCM/Crowsnest systemd units;
6. leaves the stock QIDI `webcamd` installation intact;
7. keeps the persistent backup.

The backup is intentionally retained:

```text
/home/mks/.qcm-backup
```

This makes a later reinstall capable of restoring the same original baseline.

```text

curl
ffmpeg
v4l2-utils
libevent-2.1-6
```

Crowsnest also uses standard system utilities such as:


## 26. Reboot note

A normal systemd reboot was observed to cause an unusual shutdown state on the tested QIDI firmware: the SSH connection, WebUI and printer display did not immediately return.

After a power-cycle boot the printer started correctly and the QCM/Crowsnest stack initialized normally.

The successful cold-boot result was:

```text
qcm.service             active
crowsnest-qidi.service  active
webcamd.service         inactive
/webcam/?action=snapshot
HTTP 200
JPEG 1280x720
```

This release does not modify the QIDI shutdown/boot infrastructure to work around that firmware-specific behavior.

## 32. Troubleshooting

### Camera is unavailable

Check:

```bash
systemctl is-active qcm.service
systemctl is-active crowsnest-qidi.service
systemctl is-active webcamd.service
```

Then check:

```bash
ls -l /dev/video*
```

and:

```bash
curl -sS --max-time 3 -o /tmp/qcm-test.jpg -w "HTTP=%{http_code} SIZE=%{size_download}\n" "http://127.0.0.1:8080/?action=snapshot"
```

### Crowsnest is not selected

Check:

```bash
grep '^QCM_BACKEND=' /home/mks/klipper_config/webcam.txt
```

Expected:

```text
QCM_BACKEND="crowsnest"
```

### Stock webcamd is running unexpectedly

Check:

```bash
systemctl is-active webcamd.service
```

Only one backend should own `/dev/video4`.

### Need to return to the original QIDI stack

Run:

```bash
bash install.sh restore
```

or:

```bash
bash install.sh uninstall
```

## 33. Design principles

QCM follows several principles:

```text
Do not destroy the original QIDI camera stack.
Do not depend on internet access.
Do not require Git at runtime.
Do not modify unrelated QIDI services.
Validate before applying.
Healthcheck after applying.
Rollback after failed validation.
Preserve the original pre-installation state.
Keep backend selection explicit.
```

# Русская версия

# QCM — QIDI Camera Manager 0.2.0-alpha1

QCM (QIDI Camera Manager) — лёгкий управляющий слой для системы камеры QIDI Q1 Pro.

Основная задача QCM — не навсегда заменить штатный стек QIDI, а предоставить управляемый слой абстракции, способный выбирать и обслуживать разные backend камеры с сохранением возможности отката к состоянию, существовавшему до установки QCM.

Версия `0.2.0-alpha1` сосредоточена на безопасном управлении конфигурацией, переключении backend, проверке работоспособности, откате и автономной установке/восстановлении.

## 1. Архитектура

```text
QIDI Q1 Pro
│
├── Klipper
├── Fluidd / QIDI WebUI
│
├── Штатный backend камеры
│   └── webcamd
│       └── mjpg-streamer

└── QCM
    ├── backend webcamd
    │
    └── backend crowsnest
```

## 6. Изменения Crowsnest

Встроенный runtime основан на протестированной ветке legacy/v3.

Сделаны следующие изменения:

1. Убрана обязательная проверка RTSP-бинарника.
2. Убрано определение версии RTSP.
3. Определение версии uStreamer больше не зависит от Git.
4. Определение собственной версии Crowsnest больше не зависит от `.git`.
5. Runtime может работать без Git-репозитория.
6. Используется встроенный бинарник uStreamer.

RTSP в QCM этой версии не используется.

Файл:

```text
crowsnest/libs/rtspsimple.sh
```

намеренно сохранён, чтобы минимизировать изменения протестированного legacy/v3 runtime.

## 7. Конфигурация Crowsnest

QCM генерирует:

```text
/opt/qidi-camera/config/crowsnest.conf
```

Текущая конфигурация эквивалентна:

```ini
[crowsnest]
log_path: /tmp/crowsnest.log
log_level: quiet
delete_log: true
no_proxy: false

[cam 1]
mode: mjpg
port: 8080
device: /dev/video4
resolution: 1280x720
max_fps: 30
v4l2ctl: brightness=0,contrast=1,saturation=80,gamma=84,gain=1,sharpness=2,backlight_compensation=0
```

Этот файл является runtime state и не используется как статический файл релиза.

## 8. Транзакционная модель

QCM не просто перезаписывает конфигурацию и надеется на успешный запуск.

Pipeline:

```text
parse
  ↓
validate
  ↓
capability check
  ↓
generate backend configuration
  ↓
apply
  ↓
healthcheck
  ↓
commit
```

При ошибке:

```text
apply
  ↓
FAIL
  ↓
restore known-good configuration
  ↓
restore backend state
  ↓
restore V4L2 controls
  ↓
healthcheck
```

Это предотвращает фиксацию неработающей конфигурации.

## 9. Известная рабочая конфигурация

Внутренний known-good конфиг хранится:

```text
/opt/qidi-camera/qcm/state/known_good.conf
```

Файл предназначен для root-only доступа.

Зеркальная информация может отображаться в `webcam.txt`.

Дополнительные runtime-файлы:

```text
accepted.conf
status.json
rejected.conf
rejected.reason
```

в релизный архив не входят.

## 10. Healthcheck

Healthcheck является частью процесса применения и rollback.

Проверяется:

### Backend

Работоспособность выбранного backend.

### Snapshot backend

Получение корректного JPEG через:

```text
http://127.0.0.1:8080/?action=snapshot
```

### QIDI snapshot

Проверяется:

```text
http://127.0.0.1/webcam/?action=snapshot
```

Это подтверждает работу всей цепочки до QIDI HTTP-интерфейса.

### MJPEG stream

Проверяется наличие реальных данных потока.

Так как MJPEG stream является бесконечным, timeout после получения данных не считается сам по себе ошибкой.

## 11. CLI

Запуск:

```text
python3 /opt/qidi-camera/qcm/qcm.py
```

Команды:

```text
qcm.py
qcm.py --check-config
qcm.py --self-test
qcm.py --list-controls
qcm.py --status
qcm.py --apply-once
qcm.py --dry-run
```

`--check-config` — проверка `webcam.txt`.

`--self-test` — внутренние тесты.

`--list-controls` — список V4L2 controls.

`--status` — сохранённый журнал состояния QCM.

Важно: `--status` не является независимым live-probe.

Старый `last_error` может оставаться в `status.json`, даже когда текущий QCM находится в состоянии `RUNNING`.

`--apply-once` — применить текущую конфигурацию один раз.

`--dry-run` — выполнить проверки без применения.

`--help` — показать справку.

## 12. systemd

QCM устанавливается как:

```text
/etc/systemd/system/qcm.service
```

Сервис запускается от root, потому что управляет systemd, V4L2 и защищённым runtime state.

Используется:

```text
Restart=always
RestartSec=2
```

QCM включается при установке.

---

## 13. Crowsnest systemd

Сервис:

```text
/etc/systemd/system/crowsnest-qidi.service
```

Сам по себе сервис не включается как независимый постоянный boot-service.

Его lifecycle контролирует QCM.

Нормальное состояние при использовании Crowsnest:

```text
qcm.service             enabled / active
crowsnest-qidi.service  disabled / active
webcamd.service         disabled / inactive
```

Это исключает одновременный доступ двух camera backend к `/dev/video4`.

---

## 14. Почему webcamd сохраняется

QIDI — это не только отдельный процесс камеры.

Штатная камера может быть связана с:

```text
QIDI WebUI
Fluidd
QIDI Link
внутренними сервисами
обновлениями прошивки
```

Поэтому QCM не удаляет:

```text
/usr/local/bin/webcamd
/etc/systemd/system/webcamd.service
```

Они сохраняются как полноценный rollback target.

## 15. Офлайн-установщик

В релиз входит:

```text
install.sh
```

Он рассчитан на автономную установку без загрузки runtime QCM/Crowsnest из интернета.

Внутри пакета находятся:

```text
QCM
Crowsnest
uStreamer
systemd units
пример конфигурации
лицензии
```

Git не требуется.

Официальный установщик Crowsnest не запускается.

Также не используется upstream:

```text
make install
```

Это сделано намеренно, чтобы не допустить удаления или замены штатного camera stack QIDI.

## 16. Команды установщика

```text
install.sh install
install.sh repair
install.sh restore
install.sh uninstall
```

Установщик можно запускать как root либо обычным пользователем с sudo.

При запуске обычным пользователем sudo запрашивается один раз.

Пароль в установщике не хранится.

## 17. install

```text
install.sh install
```

При первой установке:

1. проверяется окружение;
2. определяется рабочий `webcam.txt`;
3. создаётся backup исходного состояния;
4. устанавливается QCM;
5. разворачивается Crowsnest;
6. устанавливаются systemd units;
7. применяется релизная конфигурация Crowsnest;
8. управление переключается на QCM;
9. выполняется healthcheck.

Повторный `install` поверх существующего QCM запрещён.

Для существующей установки используется:

```text
repair
```

---

## 18. Persistent backup

Исходное состояние хранится отдельно:

```text
/home/mks/.qcm-backup
```

Backup создаётся один раз и не перезаписывается `repair`.

Он может содержать:

```text
webcam.txt
manifest
```

Manifest хранит:

```text
наличие файла
UID
GID
mode
enabled state webcamd
active state webcamd
```

Это позволяет вернуть состояние, существовавшее до установки QCM.

---

## 19. repair

```text
install.sh repair
```

Repair повторно разворачивает runtime текущей версии.

Исходный persistent backup не перезаписывается.

Repair предназначен для:

```text
повреждения runtime
отсутствия systemd unit
удаления части файлов
повторной установки текущего релиза
```

Текущая рабочая конфигурация QCM при этом не должна без необходимости заменяться example-конфигом.

---

## 20. restore

```text
install.sh restore
```

Restore:

1. останавливает QCM-controlled camera stack;
2. отключает QCM;
3. восстанавливает исходный `webcam.txt`;
4. восстанавливает его owner/group/mode;
5. восстанавливает записанное состояние `webcamd`.

Цель — вернуть камеру к состоянию до установки QCM.

---

## 21. uninstall

```text
install.sh uninstall
```

Uninstall:

1. восстанавливает исходное состояние;
2. останавливает QCM/Crowsnest;
3. отключает QCM;
4. удаляет runtime QCM;
5. удаляет QCM/Crowsnest systemd units;
6. оставляет штатный `webcamd`;
7. сохраняет persistent backup.

Backup остаётся:

```text
/home/mks/.qcm-backup
```

чтобы последующая установка могла использовать тот же исходный baseline.

---

## 22. Что удаляет uninstall

QCM удаляет только принадлежащие ему компоненты:

```text
/etc/systemd/system/qcm.service
/etc/systemd/system/crowsnest-qidi.service

/opt/qidi-camera/qcm
/opt/qidi-camera/crowsnest
/opt/qidi-camera/config/crowsnest.conf
```

Штатные файлы QIDI:

```text
/usr/local/bin/webcamd
/etc/systemd/system/webcamd.service
/home/mks/mjpg-streamer
```

не должны удаляться.

## 25. Протестированный lifecycle

Проверены:

```text
repair
  ↓
камера работает

restore
  ↓
штатный webcamd
  ↓
камера работает

uninstall
  ↓
штатный webcamd
  ↓
камера работает

install
  ↓
QCM + Crowsnest
  ↓
камера работает

cold boot / power cycle
  ↓
QCM active
  ↓
Crowsnest active
  ↓
камера работает
```

Проверенное состояние после запуска:

```text
qcm.service             enabled / active
crowsnest-qidi.service  disabled / active
webcamd.service         disabled / inactive
camera                   1280x720 @ 30 FPS
```

## 26. Особенность reboot

На тестируемой прошивке при обычном `systemd reboot` наблюдалось необычное поведение shutdown/boot-цепочки: SSH, WebUI и дисплей не восстановились сразу.

После полного power-cycle принтер загрузился нормально.

После загрузки:

```text
qcm.service             active
crowsnest-qidi.service  active
webcamd.service         inactive
/webcam/?action=snapshot
HTTP 200
JPEG 1280x720
```

QCM не вмешивается в shutdown/boot-механику самой прошивки.

## 33. Основные принципы

QCM придерживается следующих принципов:

```text
Не уничтожать оригинальный QIDI camera stack.
Не зависеть от интернета.
Не требовать Git во время работы.
Не изменять посторонние QIDI сервисы.
Проверять конфигурацию до применения.
Проверять камеру после применения.
Откатывать неудачные изменения.
Сохранять исходное состояние до установки.
Держать выбор backend явным.
```
